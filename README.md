# Koral Events

אתר אירועים בעברית וב־RTL, וממשק ניהול שמתוכנן קודם כול לטלפון. Next.js, TypeScript ו־SQLite עם WAL וטרנזקציות לאישור משתתפות. אין סליקה ואין שליחת הודעות אוטומטית.

## הרצה מקומית

Node.js 22.14 ומעלה נדרש.

1. `npm ci`
2. העתיקו את `.env.example` אל `.env.local`. הגדירו `ADMIN_PASSWORD` עם לפחות 12 תווים.
3. `npm run dev`
4. האתר ב־http://localhost:3000 והניהול ב־http://localhost:3000/admin.

להדגמה בלבד: הגדירו `DATABASE_PATH=./data/demo.sqlite` בקובץ המקומי, ואז הריצו `npm run seed:demo`. הסקריפט יוצר אירועים ומשתתפות פיקטיביים אך ורק ב־`data/demo.sqlite`; הוא לא נוגע במסד האמיתי. תמונות ההדגמה נוצרו באמצעות imagegen ומציגות מפגש נשים בכותל ומסיבת תחפושות לנשים. יש להחליפן בתוכן הלקוחה לפני הפרסום. אין להעלות את `.env.local`, תיקיית `data` או משתתפות הדגמה לשרת.

## ניהול

- יצירת אירוע היא שלושה מסכים קצרים: תמונה ושם, מתי ואיפה, מקומות ועלות. מעלים תמונה (JPG/PNG/WebP עד 10MB), ואז שומרים טיוטה או מפרסמים מתוך תצוגה מקדימה. אפשר להוסיף גם תמונה רחבה למחשב (לא חובה); היא מוצגת במסכים מ-1000 פיקסלים ומעלה, ובטלפון תמיד מוצגת התמונה הראשית.
- בפלייר עם טקסט בוחרים ״הצגת התמונה בשלמותה״.
- בקשה יכולה לכלול כמה מוזמנות על שם אחד (עד 6 מהאתר, עד 10 מהניהול). המכסה נספרת לפי מקומות: סכום המוזמנות של ההרשמות המאושרות. כפתור וואטסאפ פותח הודעה מוכנה; המנהלת שולחת בעצמה.
- תשלום מנוהל בנפרד מהאישור. ביטול אינו מוחק סימון תשלום, כדי שלא לאבד רישום כספי. מחיקה לצמיתות כן מוחקת אותו ודורשת אישור.
- אין קידום אוטומטי מרשימת ההמתנה. שינוי וביטול של משתתפת נעשים דרך המנהלת (בתפריט ⋯ בשורת המשתתפת).
- רשימת המשתתפות: פס מצב לפי סטטוס, צ׳יפים עם ספירה לסינון, אישור בלחיצה אחת בשורה, ״אישור כל הממתינות״ בסינון ממתינות, העתקת טלפונים של הרשימה המסוננת (לקבוצת וואטסאפ) וייצוא CSV.
- כל התאריכים והשעות מוזנים ומוצגים לפי Asia/Jerusalem, גם אם הטלפון נמצא בחו״ל.
- הרשמה כפולה אינה חושפת את פרטי ההרשמה הקיימת ואינה משנה אותם.
- אחרי הרשמה מוצעים ״הוסיפי ליומן״ (יומן גוגל, ובמכשירי אפל קובץ `.ics` מהכתובת `/api/events/<id>/calendar.ics`) ו״תביאי חברה״ (הודעת וואטסאפ מוכנה עם קישור לאירוע). אין שליחה אוטומטית.

## עדכון GitHub ופרוד

הכתובת: https://lawebs.co.il/Koralevents2 — ניהול: https://lawebs.co.il/Koralevents2/admin.
המאגר הפרטי: https://github.com/lironatar1994-coder/KoralEvents2.

מתיקיית הפרויקט ב־PowerShell:

```powershell
.\deploy.ps1 "תיאור השינוי"
.\deploy.ps1 "תיאור השינוי" -Target GitHub  # commit + push בלבד
.\deploy.ps1 -Target Prod                  # פריסת HEAD נקי שכבר נמצא ב-GitHub
.\deploy.ps1 -Target Check                 # בדיקות בלבד
```

נדרשים Node.js, Git, גישה לחשבון GitHub וחיבור SSH ל־`root@vee-app.co.il`.
הסקריפט בודק טיפוסים וטסטים ומעלה את הקוד. השרת מושך מ־GitHub רק את השינויים באמצעות deploy key לקריאה בלבד, ובונה ארכיון של אותו commit בדיוק; אין העלאה חוזרת מהמחשב של כל התמונות. בשרת מתבצעת בניית Linux עם worker יחיד ומגבלת זיכרון; האתר הקודם ממשיך לפעול עד שהבנייה מסתיימת. החלפת הגרסה מפעילה מחדש את השירות ולכן צפויה הפסקה קצרה. אם בדיקת הבריאות המקומית או הציבורית נכשלת, קוד הגרסה הקודמת מופעל מחדש. מסד הנתונים אינו משוחזר אוטומטית.

השירות `koralevents2` מאזין רק ב־`127.0.0.1:3111`, מאחורי Nginx וה־HTTPS הקיים. `NEXT_PUBLIC_BASE_PATH=/Koralevents2` נקבע בזמן הבנייה. הנתונים והתמונות נשמרים ב־`/opt/koralevents2/shared`, מחוץ לתיקיות הגרסאות. הסיסמה הראשונית נוצרת אקראית ונשמרת רק בשרת ב־`/opt/koralevents2/shared/app.env`; היא אינה מופיעה ב־GitHub. קובצי הדגמה מקומיים אינם מועתקים.

לפני עדכון מסד קיים נוצר גיבוי SQLite עקבי ב־`/opt/koralevents2/backups`. תיקיות גרסאות וגיבויים נשמרות; יש לנטר מקום בדיסק ולמחוק גרסאות ישנות ידנית תוך שמירת `current` והנתיב הרשום ב־`previous-release`. הגיבוי האוטומטי לפני עדכון אינו תחליף לגיבוי יומי וחיצוני של מסד הנתונים והתמונות.

```sh
systemctl status koralevents2
journalctl -u koralevents2 -n 100 --no-pager
curl -f https://lawebs.co.il/Koralevents2/api/health
```

ההקמה החד־פעמית של השירות מתועדת ב־`scripts/provision-linux.sh`; היא מיועדת לשרת הקיים בלבד. בנוסף מוגדר מאגר bare ב־`/opt/koralevents2/source.git` שמצביע למאגר GitHub. עדכונים שוטפים אינם משנים את Nginx. `/api/health` מחזיר גם את ה־commit הפעיל.

## פריסה חלופית עם Docker בשרת Linux

1. הגדירו DNS לדומיין ופתחו פורטים 80 ו־443. נדרשים Docker ו־Compose.
2. העלו את קוד הפרויקט בלבד. צרו `.env` עם `DOMAIN=events.example.com` ו־`ADMIN_PASSWORD` חזק (12 תווים לפחות).
3. `mkdir -p backups && sudo chown 1000:1000 backups`
4. `docker compose up -d --build`
5. בדקו `docker compose ps`, את `/api/health`, כניסה לניהול והרשמת ניסיון.

Caddy מנפיק HTTPS ומחליף את כותרת כתובת הלקוח. אין לחשוף את פורט 3000 ישירות לרשת. אם יש שרת Nginx קיים, אפשר להעביר דרכו HTTPS במקום שירות Caddy, עם הגבלת גוף של 12MB, העברת Host ו־X-Forwarded-Proto, והחלפת X-Forwarded-For בכתובת הלקוח המאומתת. `APP_ORIGIN` חייב להיות המקור הציבורי המדויק.

הנתונים והתמונות נמצאים ב־volumes נפרדים ונשמרים בעדכון הקונטיינר. יש להריץ מופע אפליקציה אחד על דיסק מקומי; אין לשתף SQLite בין שרתים או על NFS. מסד הנתונים נוצר אוטומטית בהפעלה הראשונה. `PRAGMA user_version` מסמן את גרסת הסכמה (2: עמודת `image_wide`; 3: עמודת `guests` בהרשמות). עמודות חסרות נוספות אוטומטית למסד קיים, גם על חיבור שכבר פתוח.

## גיבוי ושחזור

בשרת, גיבוי עקבי של SQLite (כולל WAL) דרך API הגיבוי שלו:

```sh
docker compose exec app node scripts/backup.mjs /backups/koral.sqlite
docker compose cp app:/app/uploads ./backups/uploads
```

יש להעתיק את שני הגיבויים גם למיקום חיצוני מאובטח. לגיבוי מסד ותמונות מאותה נקודת זמן, בצעו בחלון תחזוקה שבו אין העלאות חדשות. מומלץ גיבוי יומי ולפני עדכון גרסה.

לשחזור: עצרו את האפליקציה, שחזרו את קובץ הגיבוי ל־`/app/data/koral.sqlite` בתוך ה־volume ואת התמונות ל־volume ההעלאות. ודאו שאין קובצי `koral.sqlite-wal` או `koral.sqlite-shm` ישנים לצד המסד המשוחזר, ושבעלות הקבצים היא UID 1000. הפעילו מחדש ובדקו אירוע, משתתפות ותמונה. אין להעתיק קובץ SQLite פעיל כגיבוי רגיל ללא API הגיבוי.

## סיסמה ובדיקות

`ADMIN_PASSWORD` משמש רק ליצירת החשבון הראשון. להחלפה מקומית הגדירו `NEW_ADMIN_PASSWORD` והריצו `npm run admin:password`; כל החיבורים הקיימים יבוטלו. לשינוי בשרת השתמשו בסקריפט `scripts/rotate-password.mjs` בתוך הקונטיינר כמוסבר בקובץ; אין צורך למחוק את הנתונים.

`npm test` בודק את זרימות ההרשמה, המכסה, כפילויות, תשלומים, ארכוב, תאריכים והתמדה במסד נפרד זמני. `npm run typecheck` ו־`npm run build` בודקים טיפוסים ובניית ייצור.

לאחר הפעלת האתר המקומי עם `data/demo.sqlite`, הריצו `npm run test:browser` לבדיקות דפדפן מקצה לקצה. ב־Windows נעשה שימוש ב־Chrome המותקן; ב־Linux התקינו קודם `npx playwright install --with-deps chromium`. הבדיקות יוצרות אירוע בדיקה ומעבירות אותו לארכיון, ולא שולחות הודעות וואטסאפ. הן כוללות רוחבי 360, 390, 430 ו־1440 פיקסלים ובדיקות נגישות אוטומטיות.

פרטי תמונת האווירה שנוצרה במיוחד לאתר והפרומפט שלה מופיעים ב־`ASSETS.md`.
